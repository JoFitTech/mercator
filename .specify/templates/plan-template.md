## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Document PASS/FAIL with evidence for each Mercator constitution gate:

- **Brownfield preservation**: Identifies existing Mercator paths affected by
  the feature and explains how the current working Streamlit app remains usable
  until replacement modules exist.
- **No greenfield fork**: Confirms the work stays in this repository and does
  not create a separate app, duplicate product stack, or replacement repository.
- **Data-store separation**: Preserves MongoDB for raw API responses and MySQL
  for clean relational analysis data; lists any sync or migration impact.
- **Rename safety**: Provides a repository-analysis-backed rename map when
  insider-trade-specific concepts are broadened, and confirms imports, tests,
  UI references, docs, and database references are updated together.
- **Prediction transparency**: For predictions, rankings, preference scores, or
  forecasts, includes uncertainty, confidence, model quality, and data freshness
  in the feature design and UI.
- **Visible data quality**: Shows missing, stale, incomplete, failed, or
  low-quality data as explicit user-facing text, not only color or iconography.
- **No trade execution**: Confirms the feature does not execute trades, place
  orders, connect to brokers, or present system output as a final trading
  decision.
- **Streamlit-first UI**: Keeps Streamlit as the first UI unless a ratified
  constitution amendment says otherwise.
- **Secrets handling**: Keeps API keys and secrets in environment variables or
  approved secret-management paths; no secrets in code, specs, tests, logs, or
  docs.
